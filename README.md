# ClientFlow

Персональное рабочее пространство фрилансера: заказы, клиенты, ТЗ, правки, деньги и время. Русский интерфейс, тёмная и светлая темы, адаптивная верстка. HTML + SCSS + Bootstrap 5 + модульный JavaScript; Gulp, Supabase.

## Быстрый запуск

Требуется Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Без `.env` приложение работает локально: данные остаются в браузере, авторизация не требуется. «Посмотреть демо» открывает отдельный набор примеров; возвращение в рабочее пространство не меняет его данные. Примеры можно удалить в настройках деморежима. Локальный режим подходит для одного устройства; делайте экспорт JSON для резервной копии. Это не облачная синхронизация.

```sh
npm run build   # готовые статические файлы в dist/
npm test       # расчёты, валидация, SQL и изоляция владельцев
npx playwright install chromium
npm run test:e2e
```

Для установленного системного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. Сборку `dist/` можно разместить на любом статическом HTTPS-хостинге. Маршруты используют `#`, специальный серверный fallback не нужен. GitHub Actions проверяет сборку и тесты; автоматическое размещение сайта не настроено.

## Подключение Supabase

1. Создайте проект Supabase. Один раз выполните `supabase/schema.sql` в SQL Editor нового проекта. Скрипт создаёт 12 таблиц, RLS (доступ только владельцу), составные внешние ключи, индексы и приватный bucket `attachments`. Скрипт начальной установки не предназначен для повторного применения к существующей базе.
2. Скопируйте `.env.example` в `.env` и заполните:
   - `SUPABASE_URL` — URL проекта из Supabase Project Settings → API.
   - `SUPABASE_PUBLISHABLE_KEY` — публичный publishable key (либо прежний anon key).
   Не используйте `service_role` или secret key. `.env` исключён из Git; публичный ключ попадает в браузерную сборку, доступ защищён RLS.
3. В Authentication → URL Configuration укажите Site URL и разрешённые Redirect URLs вашего сайта (для разработки http://localhost:3000). Включите email/password. Подтверждение почты и доставка восстановления зависят от настроек Auth/SMTP вашего проекта.
4. Перезапустите `npm run dev` или выполните `npm run build`. Войдите или зарегистрируйтесь через кнопку аккаунта. После подтверждения почты войдите снова. Восстановление доступа открывает форму нового пароля по ссылке из письма.
5. После входа загружается собственное облачное пространство. Локальные и демонстрационные записи не переносятся автоматически. Это исключает случайное смешивание примеров с реальными данными.

Рабочий Supabase этой поставкой **не создан и не подключён**. SQL проверен в PGlite (PostgreSQL с тестовыми схемами Auth/Storage), включая попытки чтения, записи, изменения и удаления чужих данных. Настоящие письма, Auth redirect, Storage и сетевые ошибки конкретного Supabase требуют проверки после подключения проекта. Для финальной проверки зарегистрируйте два аккаунта и убедитесь, что они не видят записи друг друга.

## Возможности

- Обзор с реальными расчётами, поступлениями по месяцам, этапами, дедлайнами и историей.
- CRUD заказов, поиск, фильтры, сортировка, карточки, таблица, Kanban с перетаскиванием. На сенсорном экране любой этап доступен через список в заказе.
- Клиенты, контакты, список их заказов и финансовые итоги.
- Карточка заказа: ТЗ с текстовым редактором, заголовками и списками, чек-лист, файлы/ссылки, правки с раундами и приоритетами, заметки, платежи, журнал действий.
- Финансы: стоимость, плановая предоплата, фактические поступления, остатки и история. Предоплата не считается поступлением, пока не добавлен платёж. Переплата одного заказа не уменьшает задолженность другого.
- Таймер с сохранением начала между перезагрузками, ручные записи, общее время и ставка по стоимости проекта. В нескольких вкладках одновременный запуск таймеров не синхронизируется.
- Свои шаблоны ТЗ и пять готовых примеров; применение к новому или существующему заказу.
- Поиск заказов, клиентов и заметок (Ctrl/⌘ K), экспорт всех данных в JSON и заказов в CSV.
- Коммерческое предложение из заказа: «Печать / PDF» → «Сохранить как PDF» в системном диалоге браузера.
- Профиль, контактный email, валюта, часовой пояс и тема. Смена валюты меняет формат, но не конвертирует существующие суммы. Email профиля не меняет адрес входа в Auth.

## Структура

- `src/index.html` — оболочка.
- `src/scss/app.scss` — дизайн-система и адаптивность.
- `src/js/app.js` — маршруты, экраны, формы и действия интерфейса.
- `src/js/domain.js` — расчёты, валидация и демоданные.
- `src/js/store.js` — локальное хранилище, Supabase, файлы и журнал.
- `supabase/schema.sql` — схема и политики доступа.
- `tests/` — модульные, SQL и браузерные тесты.
- `tasks/001-clientflow/TASK.md` — состояние задачи и результаты.

## Практические ограничения первой версии

ТЗ — простой текстовый редактор, без форматирования rich text. Напоминания показываются в приложении, рассылок и фоновых push нет. Локальные файлы ограничены 1 МБ, облачные — 10 МБ; лимит localStorage зависит от браузера. JSON-экспорт локального режима включает файлы, облачного — метаданные приватных объектов. Импорт резервных копий пока не реализован. Удаление метаданных вложения/заказа не удаляет сам объект из облачного Storage: ненужные объекты можно очистить через Supabase Dashboard. При одновременной работе нескольких устройств нужно обновить страницу для получения чужих изменений; автоматического разрешения конфликтов нет. Рабочие пространства команд и приглашения — будущий этап; сейчас изоляция по пользователю.
